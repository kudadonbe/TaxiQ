# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

TaxiQ v2 is a visual model of the physical taxi queue at a call center. The operator calls a ride on the radio, and drivers who want it answer with their center number (`taxiNo`, e.g. 34). The operator taps each one who answers, which slides their row left and uncovers an Assign button in the gap. The slid-left driver *highest in the queue* is highlighted as the suggestion, but any of them can be assigned. **Assigning finishes the call**: the taxi moves to the back, and every slid card returns to normal. If something happens to the driver before the trip is completed, the operator **reopens** that dispatch from Recent dispatches: the driver gets their old place back, and the call returns with its passenger details and the other answering drivers. A **suspended** driver (misconduct, unpaid fees) shows the red side of their card, like a flipped physical tag. They keep their place in the queue but can't answer or be assigned. Each call can carry passenger details, and the pickup can be chosen with the house search. The app is bilingual (English/Dhivehi) and has an Admin view for registering and removing taxis.

`v2` is the **default branch**, a rewrite in React 19 + TypeScript + Vite + Tailwind CSS v4. Branch from and open PRs against `v2`. The `v1` branch (formerly `main`) holds the Angular 15 v1, so don't diff against `v1` expecting related code. There is no `main` branch.

**v3 is in progress on the `v3` branch.** When you add a feature to v2, also add it to `plans/v2-features-to-port.md` on `v3` (with the commit), so it isn't lost when v3 replaces v2.

**Direction:** TaxiQ will have two sides, **public service (taxi)** and **private hire** (people and companies offering their own vehicles), in both the app and the game; v3 grows to hiring **any land vehicle**. See `plans/product-direction.md`.

## Commands

Use pnpm (the repo has `pnpm-lock.yaml` and a local `.pnpm-store`).

```sh
pnpm install
pnpm dev       # Vite dev server, http://localhost:5173
pnpm build     # tsc -b (type-check app + node configs) then vite build to docs/
pnpm lint      # oxlint (not ESLint), config in .oxlintrc.json
pnpm preview   # serve the built docs/
pnpm deploy    # build + deploy docs/ to Firebase Hosting (needs the firebase CLI, logged in)
```

There is no test runner set up yet. `pnpm build` is the type-check gate, since `tsc -b` runs before the Vite build.

## Architecture

- There is no backend and no router. `src/main.tsx` wraps `App.tsx` in `I18nProvider`. `App` switches between three views with a local `view` state: the queue, `MapView` and `AdminPanel`. `MapView` is lazy-loaded, so Leaflet only downloads when the Map tab opens.
- All queue state lives in the `useQueue` hook (`src/useQueue.ts`):
  - `queue` is every registered taxi, in rank order.
  - `interested` is the set of drivers who answered the current call.
  - `call` is the passenger details for the call being taken (`CallInfo`). It is memory only.
  - `pick` is derived: the first taxi in `queue` that is in `interested`. Suspended taxis can never be in `interested`.
  - `history` is the dispatch log, capped at 30 and in memory only. Each `Dispatch` stores the taxi's old index (`from`), the interested set and the call.
  - The actions are `toggle`, `clear`, `assign`, `undo`, `reopen`, `suspend`, `lift`, `register`, `remove` and `reset`.
- **Undo** (latest dispatch only) takes a dispatch back as if it never happened: same index, same answered drivers, same call details. It is allowed only while `history[0].exact` is true.
- **Reopen** (any dispatch not yet reopened) moves the driver back to `from`, clamped to the queue length. It restores the call and the other answered drivers, but not the reopened driver. The entry is marked `reopened` and kept in the log. A reopen or a removal sets `exact: false` on the other entries, because their indexes may no longer match. Both undo and reopen are blocked while a call is in progress, so they never overwrite the call being taken.
- **Persistence:** full taxi records, including an optional `suspended` record (reason, note, time), are saved in `localStorage` under the key `taxiq.queue.v3`. Call details and the dispatch log are never saved. On load, each record goes back through `parseStoredTaxi`, and anything invalid or duplicated is dropped. Bump the key if the stored shape changes. The language choice is saved under `taxiq.lang`.
- **Validation:** `src/validate.ts` is the single set of allow-list rules. Both the admin form and the stored-data loader use it, and center numbers and registrations must be unique. Free text (call details, suspension notes) uses `isFreeText`: letters in any script, digits and basic punctuation, up to 120 characters. Invalid call details block Assign. Change the rules there, not in the components.
- **i18n:** `src/i18n.tsx` holds every UI string, in `en` and `dv`. Add new strings to both. Choosing Dhivehi sets `<html dir="rtl" lang="dv">`, so use logical utilities (`text-start`, `ms-*`/`me-*`) for anything that should mirror. The slide-left animation and its `pl-20` gutter are deliberately physical, so rows slide left in both languages. Each driver has `name` and `nameDv`; display it with `driverName()`. Fonts are self-hosted in `src/fonts/` (copied from the `kudadonbe.v3` repo): **MV Bodu** for all headings (`h1`–`h3`, via `--font-heading`) and **Dhanbumaa** for body text. Noto Sans Thaana (`@fontsource`) is the fallback. Their `@font-face` rules in `src/index.css` use a Thaana-only `unicode-range`, because these fonts have no Latin letters. Latin text uses the system font, and the font files only download when Dhivehi is on screen.
- **Map:** `MapView` runs on **MapLibre GL** (rotate, tilt, compass, and the geolocate control), driven imperatively. Its web worker is bundled with `?worker&url` and registered through `setWorkerUrl`; don't remove that, or GeoJSON layers such as the plots stop drawing. Labels and cars are DOM markers aligned to the viewport. Each car is rotated by `heading - map.getBearing()`, so it points the right way on a rotated map. Markers are kept in a ref and moved with `setLatLng`, so position updates never re-render React. Marker content is built with `textContent`, never HTML strings. Tiles come from tile.openstreetmap.org, which means each viewer's IP address goes to OSM. Markers are top-down car SVGs rotated to the heading every frame, with an upright number label. Positions come from `subscribePositions` in `src/positions.ts`. That is a **placeholder** that simulates taxis on **Kulhudhuffushi's** real road graph (`src/data/roads.json`). Each taxi takes random turns at junctions and avoids U-turns. Regenerate the road graph with `scripts/build-roads.py`; the OpenStreetMap download command is in its docstring. The real feed (driver app → server → WebSocket, with eFaas login) must replace that one function and keep the same `Position` shape.
- **Where the map opens:** the real app's map (`MapView` with the default position feed) asks for the viewer's location when it opens and flies there (`src/roadArea.ts`, `useArea`). **Demo taxis only ever drive on real roads, following one-way streets.** Road sources, best first: our own data near Kulhudhuffushi (`src/homeRoads.ts`), then full OpenStreetMap data from Overpass (one-way tags; main server, then a mirror; the position is rounded to about 1 km), then the road lines MapLibre reads from **OpenFreeMap** vector tiles (an invisible layer; `oneway` included). A better source always replaces a weaker one (`offerRoads`). `src/core/osmRoads.ts` builds the graph: points within 2.5 m join, roads are split where they touch or cross (simplified tiles lose junction points), and only the part where every road can reach every other road is kept (strongly connected), so no car gets stuck. Until roads load no demo taxis are shown, and if none load in 25 s the note says so. Trip routes use the same roads. If the viewer says no to location, the map stays on Kulhudhuffushi. The game map never moves. Road signs and turn restrictions aren't used yet (future: our own survey data or the v3 server).
- **Place search:** `src/places.ts` searches `src/data/places.json`, which holds 3,914 Kulhudhuffushi houses, roads, landmarks and plots with English and Dhivehi names and plot numbers. The data comes from the **Kulhudhuffushi City Council** map via mapkf.vercel.app by emjey, used with permission. Keep the credit in the map attribution and the README. The file is lazy-loaded on the search box's first focus. `scripts/import-places.py` rebuilds it, converting the site's chart positions to lat/lng with the site's own `GEO` constants. Road points line up with OSM roads to a median of about 4 m. Selecting a place drops a pin (or highlights the road) and lists the 3 nearest taxis, refreshed every second.
- **Other areas (Malé):** `src/data/places-male.json` (14,106 places) holds Malé house, place and road names from **Malé City Council**'s public lots service (8,328 named, with Dhivehi names, ward and block), and Hulhumalé named buildings and lot numbers from **HDC**, used with permission; `scripts/import-male.py` rebuilds it (run it with `/usr/bin/python3`, which has the Mac's certificates). `loadPlacesAround(at)` in `src/places.ts` adds an area's file when `at` is in its box (`REGIONS`), so it only downloads there. Search, map labels, pin names and **You're near … / Hire from here** (pickup prefilled at the viewer's location) use the viewer's area; the game stays on Kulhudhuffushi. `src/viewerSpot.ts` lets the house search know the area without loading the road data. Villimalé houses aren't in this data yet. **Postcodes:** `scripts/import-postcodes.py` adds Maldives Post postcodes (`pc`) to Malé houses by name (the road nearest the house decides when a name repeats), then by loose spelling (ee/i, oo/u, aa/a, dh/d, th/t, w/v, doubled letters) only when that postcode's road runs within 150 m of the house; 3,590 matched (3,348 exact, 242 loose). Run it after `import-male.py`. Postcodes show in search, the place card and pin names, and are searchable.
- **Plot map and labels:** `src/data/plots.json` holds the Kulhudhuffushi City Council plot chart **redrawn as vector polygons**: 3,419 plots with their ward colours. It is used with permission. Each plot carries the houses inside it (`h`, as [English, Dhivehi]) and its plot number, and 3,083 of the 3,227 houses are matched. `scripts/build-plots.py` builds it by tracing the chart's zoom-6 tiles from mapkf with OpenCV. Setup and download steps are in its docstring; numpy, OpenCV and shapely are dev-only tools, not app dependencies. `src/components/plotLayer.ts` draws the plots on a canvas renderer, and tapping a plot opens a popup built with `textContent`. The map zooms to 22, with OSM tiles upscaled past 19. Lazy-loaded data: `plots.json` (~200 KB gzipped) loads when the Map opens with "Plot map" on, which is the default. House and landmark labels appear at zoom 18+, only for what's in view and at most 400. They grow with zoom via `--map-label-size` and are styled by `.map-label` in `index.css`.
- **Call details:** `CallPanel` sits above the queue and stays collapsed to a one-line summary. `PlaceInput` suggests houses and roads, and picking one sets `pickupAt`. The Map shows that pickup as a green pin with the nearest available taxis. `DispatchLog` shows each dispatch's details, Reopen, and **Share pickup**. Share pickup sends a mapkf.vercel.app `?at=lat,lng` link, so the driver sees the house on the council map.
- **Who sees what** (`App.tsx`, from the host and the role):
  - **demo:** the GitHub Pages host. Operator screens on local data.
  - **staff:** admin or operator. Queue, Map, and Admin (admins only), plus the Passenger requests panel.
  - **driver:** role `driver` with a `taxiId`. The Driver screen (offers with Accept/Decline, accepted rides) and the Map.
  - **public:** signed out, or signed in without a role. The Hire a taxi panel and the public map, with no tabs.
  - **dev** (shown as "Developer"): role `dev`, full access for testing. The header's **👁 View as** switch (developers only) shows the app as Admin, Operator, Driver or Citizen. It only changes this screen (`viewAs` in `App.tsx`, kept for the session); the stored role stays `dev`, so the rules still allow everything. Every tab (Queue, Map, Admin, Driver, Hire). On the Driver tab, a dev can act as the driver of any taxi by setting `taxiId` on their own roles entry. In the rules, `dev` counts as admin and staff, and as a driver for its chosen taxi.
- **Hiring (no server):** `src/rides.ts` and `src/useRides.ts`. Each passenger has one request at `requests/{uid}`. A **queue** request is offered to the first taxi in `queue/state.order` that isn't suspended and hasn't been skipped. A **direct** request (a car tapped on the map) goes to that taxi only, and if it isn't accepted the passenger can send it to the queue. Each offer lasts `OFFER_SECONDS` (20). Every screen watching the request (the passenger, drivers, staff) calls `moveOn` after it times out; the rules let only one succeed, because they check `request.time`. `acceptRide` runs in one transaction: it marks the request accepted, moves the driver's taxi to the back, and logs a dispatch with a `requestId`. `firestore.rules` is the referee, so keep it in sync with any change to this flow. `publicTaxis/{id}` is the public projection of `taxis` (no phones); admin sessions keep it in sync automatically in `useLiveQueue`.
- **Two modes, one interface:** `App` picks the queue implementation from the sign-in state. Both return the same `QueueApi` (defined in `useQueue.ts`):
  - **Demo:** `useLocalQueue` in `useQueue.ts`. Signed out, or signed in without a staff role. It keeps state in this browser, and this is all the GitHub Pages copy can do.
  - **Live:** `useLiveQueue.ts`. Signed-in staff. It uses Firestore: `taxis/{id}`, `queue/state` (`{order, interested}`), and `dispatches/{id}` (never deleted; undo and reopen set `undone` or `reopened`). Every change to the order runs in `runTransaction`. Undo is exact only while the taxi is still last in the order. The call draft stays local to each operator until Assign writes it into the dispatch.
- **Auth:** `src/auth.tsx` handles Google sign-in through Firebase Auth. This is an **MDS exception** to eFaas, recorded in `SECURITY.md`. It loads `src/firebase.ts` dynamically, so the SDK isn't in the main bundle. The role comes from `roles/{email}`, which admins manage in `StaffPanel` (Admin tab). The first admin's entry has to be created in the Firebase console. In live mode, operators don't see the Admin tab, and the rules enforce the same split. `src/firebaseConfig.ts` holds the public web config; the API key is restricted to the TaxiQ domains and localhost:5173/4173. When adding any new remote origin, update the CSP in `firebase.json`.
- **Full-screen map:** the Map tab (every role) and the Hire screen fill the screen under the header (`fullMap` in `App.tsx`; `MapView fullscreen`). Everything else floats over the map: the search, the key and demo note, the trip card, and a `panel` (HirePanel), shown as a side panel on wide screens and a pull-up sheet on phones. Tapping a car opens a small see-through menu on the car (built with DOM text; it moves with the car): **Hire this taxi** (only where hiring is possible) and **Follow** (keeps it centred until the map is dragged). Hire opens the hire form, a see-through panel that collapses to a small bar. **Pick on map** in the form puts the map in pin mode (`pinMode`): a pin in the middle, a bar naming the nearest known place within 80 m, and Set here or Cancel.
- **Watching a ride:** when a ride is accepted (`activeTrip` on `MapView`), that demo taxi drives the real route to the pickup, then the destination (`driveTrip` / `tripProgress` in `positions.ts`, at `TRIP_SPEED`); the viewer moves the map freely; a see-through ride card shows the phase and minutes with **Show my taxi**. Requests now store `destinationAt` too (rules allow it). **Follow / Unfollow** from the taxi menu; a "Following taxi N · Stop" line shows while following; dragging stops it.
- **Demo rides** (developers and the demo site only, `demoAllowed` in `App.tsx`): a DEMO switch in the hire form; the taxi accepts by itself after 3 s and drives the trip. Nothing is saved, no sign-in or phone needed. The demo site has a Hire tab for this.
- **Show me on the map** (citizens, opt-in): `ShareMe` on the full-screen map's card; `useShareMe` / `usePeople` in `src/usePresence.ts`; pure rules in `src/core/presence.ts` (speed -> walking, running, cycling, e-bike, motorbike, taxi; 2-minute staleness; 1-hour limit). Two records: `presence/{uid}` with the name (staff and drivers read) and `presencePublic/{uid}` without it (signed-in users read, only when the person chose everyone). Markers are round Lucide icons rendered into the map with `createRoot`. See SECURITY.md.
- **Private vehicles for hire** (`src/vehicles.ts`; rules in `firestore.rules`, checked by `pnpm test:rules`): anyone signed in offers a car, van, pickup, motorbike or e-bike from the **My vehicles** tab (`MyVehicles`): status pending. **Any operator** approves, rejects or suspends it, with a reason to reject or suspend, in **Management → Vehicles** (`VehiclesAdmin`). Every action goes into `vehicleLog` (append-only). The owner sets the price (a trip plus per km) and can only change the price once approved. While an approved vehicle is switched to Available, the owner's device puts it on the map (`publicVehicles`, no phone number, hidden 2 minutes after the last update). Center taxis stay as they are (admins, Management → Taxis). **Booking (part 2, `src/privateRides.ts`):** tap a private vehicle, then **Hire this vehicle**, to open `PrivateHirePanel` (pickup and destination by search or pin, phone, note, the owner's price estimated from a straight line × 1.3). This writes `privateRides/{passengerUid}`: offering, then accepted (the owner's first name and phone are shared) or declined (60 s to answer), then onboard, then done; the passenger can cancel before pickup. Owners see `IncomingRides` on every screen. The passenger watches the vehicle on its real position (`privateRide` on `MapView`, Show my vehicle, Follow). Only the passenger, the owner and staff can read a booking. Demo rides are only on the demo site now.
- **Mobile navigation:** tabs show an icon with a small label on phones and the icon plus the name on wider screens (`TAB_ICONS` in `App.tsx`); header buttons (Undo, language, sign out) are icon-only on phones, with `aria-label`.
- **Management tab** (was Admin; `ManagementView`): sections **Users** (`PeoplePanel`, live and admins only) and **Taxis** (`AdminPanel`: register, suspend, remove).
- **People (Management → Users):** `PeoplePanel` lists everyone who has signed in. Each sign-in writes `users/{uid}` (email, name, `createdAt`, `lastSeen`), and only the person can write their own profile. The panel shows each person's role from `roles/{email}`; "citizen" means no role. Admins and devs filter, search and change roles inline. Only a dev can give, change or remove `dev` (enforced in `firestore.rules`).
- **Translation fixes:** the ✏️ button in the header (admins and devs) opens `TranslationEditor`. It lists every label from `builtInStrings` flattened to dotted keys; function strings become `{1}`, `{2}` templates (`src/translations.ts`). Fixes are saved to `translations/dv`, read by everyone and written only by admins and devs, and `App` subscribes and applies them live through `I18nProvider` (`dvFixes`). Export copies them as English → Dhivehi pairs so they can be written back into `src/i18n.tsx`. Keep `rowLabel`-style conditional labels out of the editor (`NOT_EDITABLE`).
- **Trip routes:** `src/core/route.ts` (Dijkstra on `ROAD_GRAPH` from `positions.ts`; taxis follow one-way streets, walking doesn't) with tests, including one on the real roads. `MapView`'s `trip` prop draws the route, its pins, and a distance/time card with a Taxi/Walk switch. If either end is far from the road graph (another island), it draws a dashed straight line instead. `CallInfo.destinationAt` holds the destination's position when it was picked from the search.
- **Reorder / shuffle (staff):** `src/core/reorder.ts` (move, shuffle, validReorder, reasonOk) with tests. The **↕ Reorder** button opens `ReorderPanel`, and saving needs a reason (late / returned / correction / shift / other + note). Live mode runs `useLiveQueue.reorder` in one transaction: it refuses if the queue changed meanwhile (`queue_changed`), writes the order, and adds a `queueChanges/{id}` log entry that can't be edited or deleted. `QueueChangesLog` shows the latest changes.
- **Online now:** `auth.tsx` refreshes `users/{uid}.lastSeen` every minute while the tab is visible. People counts anyone seen in the last 150 s as online (green dot, Online filter, online count per role).
- **TaxiQ Game (G1, G2):** design in `plans/game-mode.md`, player guide in `plans/how-to-play.md` (update it with each phase). The code is in `src/game/` (rooms: `gameData.ts`; the 🎮 Game tab: `GameTab.tsx`; car feed: `gamePositions.ts`) and `src/core/gameSim.ts`, which holds the seeded, deterministic `GameCar` walk, `gameClock`, `PRESETS` and join codes, with tests. Data is `games/{id}` (only the host updates it), `games/{id}/players/{uid}` (own entry only) and `gameCodes/{code}` (create-only, cross-checked with `getAfter`), all completely separate from the real service. G2 adds `games/{id}/cars/{n}` (a `plan`: roam or path), `trips/{id}`, `world/roster` (the world's people, made once) and `engine/lease`. The ride service is `src/core/gameEngine.ts` (`engineStep`, pure, with tests), run by `src/game/useGameEngine.ts` on whichever device holds the lease. Fares are in `src/core/fares.ts` (placeholders). `games/world` is the shared, always-running **TaxiQ World**. Car positions are never stored: every device computes them from each car's plan and the game time (`SIM_RATE`). **G3 money:** `src/core/money.ts` (placeholder prices, KD-Bank offers, money calendar: 1 real minute = 1 money day) and `src/core/moneyEngine.ts` (`moneyStep`, pure: settles money days, handles applications; money only moves between accounts, checked by tests), saved by `src/game/moneyData.ts` into `money/state`, `wallets/{uid}`, an append-only hash-chained `ledger/{seq}` and `applications/{id}`; only the engine writes money. `WalletPanel` shows the wallet, deals, offers and the open ledger. Game roles are citizen, driver, operator (queue board) and owner; app-role `dev` users get a **View as** bar to switch them in one tap. Check rule changes with `pnpm test:rules` (Firestore emulator, needs Java).
- **Seed data:** `src/data/taxis.ts` holds the default taxis, used on first run and by Reset. Its phone numbers are masked. The Admin list shows them with a **Demo** badge.
- **Deploy:** the build output is `docs/` (Vite empties it on every build, so never hand-edit it or put other files there), and it is published in two places:
  - **Firebase Hosting**, project `kd-taxiq` (`.firebaserc`), at https://kd-taxiq.web.app. Deploy with `pnpm deploy`. `firebase.json` serves `docs/` and sets the security headers (CSP, HSTS, nosniff, referrer policy, no framing). When adding a third-party origin (e.g. Firestore or eFaas), add it to the CSP or it will be blocked. **Firestore** (default database, Native mode, `asia-southeast1` Singapore, delete protection on) holds the live data. Deploy rules with `firebase deploy --only firestore:rules`. Never loosen the rules to `if true` or to any signed-in user: access must always go through `roles/{email}`.
  - **GitHub Pages**, serving `docs/` from the `v2` branch, at https://kudadonbe.github.io/TaxiQ/. It updates when `docs/` is committed and pushed.
  `vite.config.ts` uses `base: './'`, so the same build works at both the Firebase root and the Pages `/TaxiQ/` path.
- **Mobile:** the layout targets phones first (~375 px). On small screens the queue rows hide the plate and avatar, the queue count moves into the Queue tab, and tap targets are at least 40 px. Keep the `pl-20` gutter, because the Assign button needs it.
- **Styling:** Tailwind v4 through the `@tailwindcss/vite` plugin. There is no `tailwind.config`; theme tokens go in the `@theme` block in `src/index.css`.

## Conventions

- TypeScript is strict about unused code (`noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`, `verbatimModuleSyntax`). Use `import type` for type-only imports, and don't use enums or parameter properties.
- Code style is 2-space indent and single quotes in TS, with no semicolons. See `.editorconfig`.
- **No emoji anywhere in the UI** (buttons, labels, badges, strings, map). Use **Lucide** icons (`lucide-react`): import them directly, or use the helpers in `src/components/icons.tsx` (`PlaceTypeIcon`, `TripLine`) and the class names in `src/components/iconStyles.ts` (`ic`, `icFlip` for arrows that mirror in Dhivehi). Decorative icons get `aria-hidden`; meaning comes from text or an `aria-label`.

## Security standard

The workspace requires the MDS Secure Software Development Standard (see `../CLAUDE.md` and `kudadonbe/standards/mds/checklist.md`). `SECURITY.md` is in the **repo root**, because `docs/` is the Pages build output. It records **Tier 1 for the planned system** (public-facing, with personal data) and lists the blockers before real data. Update it when adding auth, a backend or real data.
- The admin panel has **no authentication**, since there is no server to enforce it. Any real deployment needs a backend with eFaas login, and the client-side panel must not be treated as access control.
- Real phone numbers, photos and other personal data must not go into the seed file or the repo.
